# 设计与边界

nano-code 由 Python 执行内核、持久化知识层和 Vue 工作台组成。模型通过 OpenAI 兼容接口接入；模型建议不能绕过执行器的权限检查。

## 执行闭环

用户任务进入会话 → 拼装稳定系统前缀、历史与检索上下文 → 请求模型 → 解析工具调用 → 检查路径与权限 → 等待必要审批 → 执行并记录事件 → 返回工具结果 → 继续迭代或结束。每轮有步数上限；每个会话同时只运行一个任务。

## 数据分层

会话消息用于恢复对话；知识记录区分情景、过程和用户偏好；大输出以内容散列寻址，消息内仅保留摘要与检索引用。技能采用声明式元数据与文本指令，候选技能进入待审核区。

## 安全边界

- 默认仅服务本机，校验 Host 与 Origin；不作为公网多用户服务部署。
- 文件访问以工作区为根，解析真实路径，拒绝路径穿越、符号链接越界、敏感文件及 Git 内部目录。
- 修改文件和执行命令均需逐次批准。审批绑定具体运行与参数，不把模型输出视为授权。
- 命令执行使用本机用户权限；确认执行命令相当于允许该命令访问本机资源。这不是操作系统沙箱。
- 文件、工具和检索结果均为不可信内容，不能提升权限；提示词规则与检测只能降低风险，不能保证阻断所有提示注入。
- 会话与记忆存放在本地数据目录，不加入 Git。不要把密钥写入对话。

## 验证原则

行为测试覆盖真实文件系统、持久化数据库、HTTP 协议和审批状态变化。用于验证协议的脚本模型响应与真实模型效果分开记录。构建成功不代表模型推理质量得到验证，缓存友好的上下文组织也不等于已经测量的成本收益。
